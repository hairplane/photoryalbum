# [인수인계/논의 정리] 우리가족 캘린더 (photoryalbum) - 배포 구조 개선안

## 1. 개요
- 본 문서는 일반 사용자(개발 지식이 없는 가족 및 지인)가 복잡한 GitHub 소스 코드 수정 과정 없이 손쉽게 '나만의 가족 캘린더'를 구축할 수 있는 구조적 개선 방향에 대한 사전 논의 내용을 담고 있습니다.
- 향후 AI와 새로운 대화를 시작할 때 이 마크다운 블록을 그대로 제시하여 별도의 긴 논의 없이 바로 구현 작업에 착수할 수 있도록 합니다.

---

## 2. 핵심 논의 사항 및 결정된 방향

### ① '나만의 캘린더' 배포 및 사용 구조 개선
- **문제점:** 일반 사용자에게 GitHub 저장소를 포크하고 소스코드 내의 `csvUrl`, `scriptUrl` 등을 직접 수정하여 배포하라는 것은 현실적으로 불가능에 가까운 높은 진입장벽임.
- **개선 방안 (SaaS형 웹 앱 구조):**
  1. 메인 웹사이트(단일 정적 페이지)는 하나로 통합하여 운영 및 유지보수.
  2. 사용자가 처음 접속했을 때 설정 모달(또는 ⚙️ 버튼)을 통해 **[내 구글 스프레드시트 CSV 링크]** 및 **[내 앱스크립트 웹앱 주소]**를 입력할 수 있도록 인터페이스 제공.
  3. 입력된 주소값은 브라우저의 `localStorage`(로컬 저장소)에 안전하게 저장하여, 이후 해당 브라우저에서는 사용자 개인의 구글 시트 데이터를 기반으로 캘린더가 렌더링되고 일정이 등록되도록 구현.
  4. 일반 사용자는 제공되는 '구글 시트 템플릿 복사 링크'를 통해 본인 드라이브에 시트만 복사한 뒤 링크만 연동하면 즉시 사용 가능하도록 가이드 제공.

## 3. 향후 구현 시 체크리스트 (Next Implementation Checklist)
1. **설정 관리 인터페이스 구현:** 웹 화면 상에서 개인별 구글 시트 URL 및 앱스크립트 주소를 입력·저장할 수 있는 설정 모달 추가 (`localStorage` 연동).
2. **동적 데이터 소스 바인딩:** 코드 내 하드코딩된 `csvUrl`과 `photoDbCsvUrl` 등을 로컬 스토리지에 저장된 사용자 커스텀 URL 값으로 우선 대체하여 로드하도록 로직 수정.
3. **가이드 문서(README) 보완:** 일반 사용자가 1분 만에 템플릿 시트를 복사하고 웹에 연동할 수 있는 스크린샷 기반의 친절한 세팅 가이드 작성.
