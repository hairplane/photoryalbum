## [설계 논의] 사진 보관 및 연결 UX 방식

Zero-Server(사용자 개인 구글 드라이브 스토리지) 구조에서 일반 사용자가 새 사진과 이야기를 등록할 때의 경험(동선) 설계입니다.

### 드라이브 업로드 처리 방식 비교

* **방식 A (원스톱 웹 업로드 - 추천)**
  * **동선:** 캘린더 화면의 등록 팝업창에서 사진 파일을 드래그 앤 드롭(Drag & Drop)하여 즉시 등록.
  * **메커니즘:** 백엔드(GAS)가 사용자의 구글 드라이브 지정 폴더에 사진을 자동 업로드하고, 발급된 `File ID`를 `Photos` 시트에 자동 기입.
  * **장점:** 사용자가 구글 드라이브 폴더를 직접 열 필요가 없어 일반 상용 앱과 동일한 매끄러운 UX 제공.

* **방식 B (드라이브 폴더 일괄 동기화)**
  * **동선:** 사용자가 구글 드라이브의 전용 폴더에 사진들을 미리 넣어두고, 캘린더 화면에서 [동기화/불러오기] 버튼 클릭.
  * **메커니즘:** 사진의 메타데이터(EXIF 촬영일자, 파일명 등)를 읽어 시트로 일괄 추출 및 적재.
  * **장점:** 수십~수백 장의 과거 사진을 한 번에 대량 마이그레이션할 때 효율적.

> **권장 전략:** 초기 일상 기록용 기본 동선은 **방식 A(웹 팝업 원스톱 등록)**를 채택하고, 과거 대량 사진 등록을 지원하는 보조 도구로 **방식 B(폴더 일괄 동기화)**를 단계적으로 연계.
